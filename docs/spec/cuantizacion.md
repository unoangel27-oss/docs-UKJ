# `p_p` Quantization — §4

- The official term is **quantization `p_p`** (that is what the user calls it; "density" remains a synonym). **It measures subparameters per parameter, not bits.** `p5_p` = 5 subparameters per parameter.
- `p_p` = official alias of `p1_p`. **`p0_p` does not exist** (zero subparameters = dense model without UKJ). Phase 1: `p1_p`–`p7_p`; top `p8_p`.

## Scope

- Per tensor (parameter node); inherits the model default if not declared.
- **Mix allowed** (`p5_p` in one part, `p2_p` in another of the same file).
- A route can override the density of its subtree (`route/capa3/p_p`).

## Relation with `q*`

- `q*` = bits per weight with inherited GGUF semantics (q4_0 = 4, q4_k = 4, q5_* = 5, q8_0 = 8…).
- `q*` is **orthogonal** to `p_p`. GGUF blocks (group size, scales, zero points) only for `q*`; `p_p` does not use blocks.

## State in phase 1

- Requantize in flight: **no** in phase 1 (offline conversion only; reserved for v2).
- Quality/performance table by code: generated by the tooling (Python) and published in the documentation; benchmarks in team CI.
- Degradation above `p8_p`: F1.2 experiment — convert OLMoE to `p1_p`…`p12_p`, same evaluation suite (perplexity + short QA) per variant; metric = perplexity delta vs `p1_p` + tokens/s + RAM; the "much degradation" threshold is set with the first baseline, not before.
